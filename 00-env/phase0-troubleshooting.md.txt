## 一、 本地开发环境配置

### 1. Git 安装与配置
*   **报错现象**：`'git' 不是内部或外部命令`。
*   **原因**：Windows 未安装 Git 或未配置环境变量。
*   **解决**：去官网或国内镜像（如淘宝 NPM 镜像）下载安装。安装后**必须重启终端**才能生效。
*   **GitHub 加速**：使用 Watt Toolkit 进行本地反向代理加速，解决国内 `clone` 和 `push` 慢的问题。
*   **SSL 证书报错**：开启代理后执行 `git clone` 报 `SSL certificate problem`。
    *   **解决命令**：`git config --global http.sslbackend schannel` （让 Git 使用 Windows 系统证书库）。
*   **首次提交身份报错**：`Author identity unknown`。
    *   **解决命令**：
        `git config --global user.name "你的名字"`
        `git config --global user.email "你的邮箱"`
    *   **中文乱码补丁**：`git config --global core.quotepath false`
*   **凭据弹窗**：`git push` 时弹出 GitHub 授权窗口，选择 `Sign in with your browser` 授权即可，后续会通过 Windows 凭据管理器自动记住。

## 二、 云服务器 (阿里云 ECS) 配置

### 1. 无法访问外网 (ping 百度不通)
*   **报错现象**：`curl` 卡死，`ping 223.5.5.5` 100% 丢包。
*   **原因**：购买实例时未分配公网 IP，或带宽峰值为 0 Mbps。
*   **解决**：去阿里云控制台 -> 实例详情 -> 更改带宽 -> 计费方式选择“按使用流量”，峰值设为 5 Mbps。

### 2. 网站无法从公网访问
*   **报错现象**：服务器内 Nginx 已启动，但本地浏览器访问公网 IP 超时。
*   **原因**：阿里云安全组未放行对应端口（默认只开放了 22 SSH 端口）。
*   **解决**：在 ECS 控制台 -> 安全组 -> 配置规则 -> 入方向，手动添加规则：允许 TCP 80 端口，授权对象 `0.0.0.0/0`。

## 三、 网络基础与抓包实战 (tcpdump)

### 1. TCP 三次握手与四次挥手
*   **抓包命令**：`tcpdump -i any -nn port 80 -S`
    *   `-i any`：监听所有网卡
    *   `-nn`：不解析 IP 和端口为域名
    *   `-S`：显示绝对序列号
*   **关键标志位 (Flags)**：
    *   `[S]`：SYN（请求建立连接）
    *   `[S.]`：SYN+ACK（同意连接并确认）
    *   `[.]`：ACK（确认收到）
    *   `[P.]`：PUSH（推送数据，如 HTTP 响应）
    *   `[F.]`：FIN（请求断开连接）
*   **面试题考点**：
    *   **为什么是三次握手**：为了确认双方的**发送能力**和**接收能力**都正常，防止历史失效的 SYN 包突然到达服务端导致资源浪费。
    *   **seq 和 ack**：`seq` 是数据包编号（防乱序、防丢失），`ack` 是确认收到的编号（下一步期望收到的编号）。
    *   **源端口随机性**：客户端发起请求时，源端口是随机分配的高位端口（如 48798），目的是为了区分同一台电脑上的多个并发连接（Socket）。

## 四、 Linux 服务排障基本步骤
1.  **看服务状态**：`systemctl status nginx` （关注 Active 是 running 还是 failed）。
2.  **看端口监听**：`ss -tlnp | grep :80` （确认服务是否真的在监听端口）。
3.  **看日志**：`tail -n 20 /var/log/nginx/error.log` （查看具体报错原因）。
4.  **重启服务**：`systemctl restart nginx`。
