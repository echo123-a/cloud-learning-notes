## 六、 阶段扩展：Docker 容器化初体验

### 1. 国内网络环境安装 Docker 踩坑实录
*   **报错现象**：执行官方一键安装脚本 `curl -fsSL https://get.docker.com | bash` 时，报错 `curl: (35) OpenSSL SSL_connect: Connection reset by peer`。
*   **原因**：Docker 官方源在国内网络环境下不稳定，TLS 握手被阻断。
*   **解决**：改用**阿里云镜像源**安装。
    1. 配置阿里云的 GPG 密钥和软件源。
    2. 执行 `apt install docker-ce` 安装。
*   **面试延伸**：在排查网络问题时，如果遇到 `Connection reset by peer`，通常意味着链路上的防火墙或代理主动重置了连接，此时应更换国内镜像源。

### 2. 配置 Docker 镜像加速器
*   **痛点**：Docker Hub 服务器在国外，拉取镜像（如 Nginx、Ubuntu）极慢甚至超时。
*   **解决方案**：修改 `/etc/docker/daemon.json`，配置国内公共加速器（如 DaoCloud：`https://docker.m.daocloud.io`），修改后需执行 `systemctl daemon-reload` 和 `systemctl restart docker` 使其生效。

### 3. 容器初体验：一句话跑起 Nginx
*   **执行命令**：`docker run -d -p 8080:80 nginx`
*   **背后的原理（核心考点）**：
    *   `run`：创建一个新的容器并运行。
    *   `-d`：Detached 模式，让容器在后台运行（类似 systemctl 的后台守护）。
    *   `-p 8080:80`：端口映射。**格式为 `宿主机端口:容器内端口`**。将云服务器的 8080 端口映射到容器内部的 80 端口。外部访问云服务器的 8080，Docker 会通过 iptables 规则将流量转发到容器内的 80 端口。
    *   `nginx`：指定使用的镜像名称。本地没有会自动从加速器拉取。

### 4. 与传统部署的区别
*   **传统部署（前面的 Python 项目）**：需要手动安装 Python、pip、依赖库，再配置 systemd 守护进程。环境一旦改变（比如换台机器），可能无法运行。
*   **容器化部署（Docker）**：将应用及其所有依赖打包成一个镜像。运行环境完全隔离，做到“**一次构建，到处运行**”。
